## 1. PROJECT OVERVIEW

### Purpose
UltraGym is a multi-club gym management SaaS. The backend (Laravel) is done and documented. This workspace holds the **four Flutter frontends**, which are the real implementation of the UI/UX prototype the user designed in earlier conversations, built on that backend.

## 6. WORKING RULES

### User instructions (verbatim intent)
- Every project has its own CLAUDE.md that **must be read before any modification or addition**.
- Projects stay **separate and independent** (own assets, pubspec, design package copy).
- Rules come from the methodology guide; the frontends are the real implementation of the user's UI/UX prototype; backend is the documented Laravel API.
- Skills come from GitHub (official/reputable sources) and must fit the methodology.
- The user writes in Arabic (Syrian/Levantine); reply in Arabic.

### Non-negotiable coding rules (engineering-rules §1)
No `setState` anywhere (only infra StatefulWidgets like `OnInit`); no file over 300 lines; Bloc/Cubit only; no hard-coded design values (`Color(0x..)`, raw `TextStyle`, magic spacing, raw `Duration`, raw radii) or route strings in screens; four states on every screen (shimmer, error+retry, empty invitation, content); no exception reaches the UI (`ApiResult`); UI branches on `FailureType`/`code`; all edits via `FormDialog`/`AppFormCubit`; features import only `core/core.dart`; Arabic RTL, both themes; reduced motion; no overflow at 360px; `flutter analyze` clean; after `await` check `context.mounted` / `isClosed`.

### Architecture conventions
Feature = `domain/models/x_models.dart` (hand-written `fromJson` with `json_x`, Equatable, no code-gen) → `data/repo/x_repository.dart` (abstract interface) → `data/datasources/x_remote_datasource.dart` (ApiClient) → register in `feature_injection.dart` → `presentation/bloc` (Slice-based) → `Routes` + route → screen. Events past tense (`XRequested`); no bloc-to-bloc dependency (screens relay, e.g. LoginCubit → screen → AuthBloc). Backend golden rules: never compute statuses/amounts; send `Idempotency-Key` on money/check-in/create; `*_at` UTC → club time, `*_on` as-is; hide what permissions disallow.

### Never change without asking
- `packages/ultragym_design` (generated; brand source of truth).
- The approved package list (add nothing outside it without asking).
- Player Android settings (AGP 8.9.1, compileSdk 36, NDK 27.0.12077973, minSdk 23) and `app_settings ^6.1.1`.
- The approved design (prototype pages, identity rules).
- Project separation / folder layout; CLAUDE.md priority order.
- Don't commit/push or create a git repo unless asked.

### Testing conventions learned
- Feature widget tests: wrap with `MediaQuery(disableAnimations: true)` (login ornaments animate forever) and **never `await bloc.stream` inside `testWidgets`** (fake async hangs) → check `bloc.state` after `pumpAndSettle`.
- Web projects' tests run on the VM: core uses conditional-export stubs (`token_store_stub.dart`, `blob_opener_stub.dart`) so `core.dart` compiles without `package:web`.
- Tests use `flutter_test` only (no bloc_test/mocktail added), fakes like `FakeAuthRepository`, `FakeAdapter` (Dio).
